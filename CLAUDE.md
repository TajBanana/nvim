# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A personal Neovim configuration (~/.config/nvim) using **lazy.nvim** as the plugin manager. Also includes a `.wezterm.lua` (WezTerm terminal config), `.ideavimrc` (IntelliJ IdeaVim config), `starship.toml` (shell prompt), `lazygit/config.yml` and `git/delta.gitconfig` in the same repo (see [Symlinks](#symlinks)).

Requires Neovim **v0.12+**: the pinned nvim-treesitter `main` branch requires 0.12, and the config uses 0.12-only APIs (`vim.diagnostic` `jump.on_jump`, the experimental `ui2` message UI). Uses the native `vim.lsp.config`/`vim.lsp.enable` LSP API (not null-ls).

## Architecture

**Entry point:** `init.lua` loads core settings then bootstraps lazy.nvim, which auto-discovers plugin specs from `lua/plugins/`. A fresh bootstrap clone is checked out at the `lazy.nvim` commit in `lazy-lock.json` (lazy.nvim cannot restore itself), and luarocks support is disabled (`rocks = { enabled = false }`; no plugin needs it, and leaving it on made `:checkhealth` report a hererocks ERROR).

**Two key directories:**
- `lua/tajbanana/set.lua` — Core Vim options and global keymaps (leader = Space), custom filetype detection (plus a `{{/* %s */}}` commentstring for helm/gotmpl), and the experimental 0.12 `ui2` message UI (so `cmdheight=0` never raises "Press ENTER"). Regression checks: `scripts/tests/set_lua.lua` (filetype rules, `<leader>go`, `<Esc>`, repaint throttle). Loaded first, before plugins. It initializes core helpers; plugin-specific helpers are initialized by their plugin specs.
- `lua/plugins/` — Each file returns a lazy.nvim plugin spec table (or list of tables). Lazy auto-loads all files in this directory.

**`lua/tajbanana/` modules** (standalone Lua helpers, not plugin specs):
- `forge.lua` — **forge shortcuts** (`<leader>gm` open/create PR/MR; `<leader>gl` commit-SHA **permalink** to the file/line or visual range, opened and copied to the clipboard — refuses when HEAD is not on the remote or the file is not in HEAD, warns when the file has uncommitted edits, works on a detached HEAD; regression checks: `scripts/tests/forge_permalink.lua`). GitHub vs GitLab is detected per buffer from the *remote host*, not from the machine, so one config serves a personal GitHub box and a work GitLab one: a `git config --local nvim.forge <github|gitlab>` override wins, else the host's dot-separated labels are matched (so `notgitlab.com` is refused), with ssh host aliases resolved through `ssh -G`. `<leader>gm` prefers `gh`/`glab` and falls back to a token-free `git ls-remote` of the forge's change-request head refs. All URL-shape differences live in the `FORGES` table; adding a forge means adding an entry, not another module.
- `system_open.lua` — opens a file/URL with the OS handler (`open` / `explorer.exe`+`wslpath` / `xdg-open`, via `flatpak-spawn` inside Toolbx) and reports failures; used by `<leader>go` (which only hands over real on-disk paths, and in nvim-tree opens the node under the cursor) and `forge.lua`.
- `env.lua` — PATH bootstrapping for node (nvm lazy-load, honouring nvm's `default` alias) and cargo/rustc (rustup) when they're missing from PATH, plus a SDKMAN JDK override that runs even when `java` already resolves.
- `terminal.lua` — the F2 bottom terminal-split toggle (normal and terminal mode); the terminal's window is looked up in the current tabpage on each press, and in a tab's last window it switches to the alternate buffer instead of closing (E444). A terminal whose shell has exited is replaced rather than reopened (and wiped unless another window, e.g. in another tab, still shows it — deleting it would close that tab). Regression checks: `scripts/tests/terminal_toggle.lua`.
- `indent_scope.lua` — cursor-based indent-blankline scope lookup for Kotlin, TypeScript/TSX, JavaScript/JSX, YAML (including the compound `yaml.helm-values` / `yaml.docker-compose` / `yaml.gitlab` filetypes), Helm’s injected YAML, Lua (multi-line tables and calls are scopes) and Python (multi-line dicts/lists/sets/tuples/calls); initialized from `ui.lua`. Skips single-line scopes except Kotlin properties. Regression checks: `scripts/tests/indent_scope.lua`.
- `incremental_selection.lua` — treesitter incremental selection (`<M-Up>`/`<M-Down>`); the node stack is buffer-scoped and dropped when visual mode ends or the buffer is edited. Regression checks: `scripts/tests/incremental_selection.lua`.
- `completion.lua` — **intentionally NOT wired into nvim-cmp.** A `cmp.confirm` wrapper that skipped one `)` after accepting a value; unwired because on multi-parameter calls it jumped out of the parentheses after the first argument. Kept with its test for a possible single-parameter-only revival — see its header and `docs/design-decisions.md`.
- `kotlin_update.lua` / `kotlin_update_prompt.lua` — the `:KotlinLspUpdate` / `:KotlinLspRollback` controller (async script run, fidget progress, retry/fallback prompts, shared in-editor guard, client restart) and its small confirmation float, which waits for normal mode so it never eats typed keys. `kotlin_update.install_root()` (`KOTLIN_LSP_HOME`, else `~/.local/share/kotlin-lsp`) and `point_at_current()` (sets `KOTLIN_LSP_DIR` to the `current` symlink path unless the user exported one; called at load and before every restart, so a first install attaches) are what `kotlin.lua` launches the server through. Regression checks: `scripts/tests/kotlin_update_flow.lua`, `kotlin_update_prompt.lua`, `kotlin_launch.lua` (real kotlin.nvim: which build a restart / first install actually runs), `kotlin_expiry_current.lua`, and the offline updater suite `test_kotlin_lsp_update.py`.
- `gitutil.lua` — shared git-toplevel resolution (used by `forge.lua`, `repo_diagnostics.lua`, `git_pickers.lua` and `plugins/telescope.lua`; the gutter in `plugins/git.lua` uses gitsigns' own repo root instead).
- `platform.lua` — OS detection (`mac` / `wsl` / `linux` / `windows` booleans plus a mutually exclusive `name`). Note WSL is *also* Linux, and nvim has no per-distro flag — Ubuntu/Debian/Arch all report `linux`. Every OS test in the config goes through here.
- `git_pickers.lua` — the `<leader>gc` / `<leader>gh` commit-history Telescope pickers, previewed through git-delta. Uses `new_termopen_previewer` because delta only runs when git's output is a tty; delta options are passed with `git -c`, and the preview terminal runs with `GIT_PAGER=delta` so a user's `GIT_PAGER`/`pager.show` cannot take over (without delta: `git --no-pager`). Both pickers work on the current file's repo; `<leader>gc` falls back to the cwd's repo, `<leader>gh` refuses a file outside git. The preview is `git show --format= --diff-merges=first-parent` (merge commits vs their first parent, root commits in full); side-by-side is chosen from the preview pane's width. Regression checks: `scripts/tests/git_pickers.lua`.
- `repo_diagnostics.lua` — repo-wide lint (`<leader>xr`). Runs one tool for the **nearest** ancestor project of the current file that carries a marker (bounded by the git root; deepest wins, detector order breaks ties): golangci-lint (else `go vet`), `cargo check`, ruff, ESLint (`-f json`) / tsc (the local binary, searched up to the git root so workspace-hoisted tools are found), `helm lint`, yamllint (only with a `.yamllint*` config), hadolint. Regression checks: `scripts/tests/repo_diagnostics.lua`.
- `tailwind_root.lua` — root detection for the tailwindcss server (`lsp.lua`'s `root_dir`); nil means it does not start. Regression checks: `scripts/tests/tailwind_root.lua`.
- `flow_pragma.lua` — whether a JS/JSX buffer carries a Flow `@flow` pragma (a whole word in a comment); ts_ls's `root_dir` in `lsp.lua` vetoes such buffers. Regression checks: `scripts/tests/flow_pragma.lua`.
- `definition_picker.lua` — the `<leader>gd` flat def/type/impl/ref Telescope picker (wired from `lsp.lua`'s `LspAttach`, not `set.lua`); opens after `M._timeout_ms` (3 s) with partial results if a server is silent, and keeps every kind of a shared location. Regression checks: `scripts/tests/definition_picker.lua`.
- `inlay_tint.lua` — re-tints inlay hints per LSP kind (type vs parameter), matching each rendered chunk to its hint by label text; set up from `lsp.lua`. Regression checks: `scripts/tests/inlay_tint.lua`.
- `lsp_status.lua` — the lualine statusline LSP-load indicator (✓ ready / ⟳ loading / ✗ expected-but-not-attached / ⏱ kotlin-lsp build EXPIRED / ○ no server, beside the filetype); required at render time from `ui.lua`'s `lualine_x`. Tracks each filetype's single PRIMARY server (see the module's `PRIMARY` table — keep it in sync with `lsp.lua`'s `ensure_installed`, including its toolchain gates: rust only with rustc+cargo, go only with `go`, and without npm the npm-built servers (`NPM_SERVERS`, mirroring `lsp.lua`'s `known_kind`) only when their binary is on PATH, i.e. already installed — checked by binary name, since five of them have function `cmd`s in lspconfig — regression checks `scripts/tests/lsp_status_gates.lua`; except `kotlin_lsp`, which is intentionally absent from `ensure_installed` because it is self-managed) and waits on LSP work-done progress so ✓ means finished loading, not merely attached. The ⏱ is a kotlin-only special case of ✗: a Kotlin buffer with no `kotlin_lsp` client ~10s after opening triggers a scan of the LSP log tail for `intellij-server has expired` / `kotlin-server has expired` (lines for a different installed version are ignored); on a hit it shows ⏱ and pops a one-shot small floating prompt (`M._prompt_expired`, `y`/`n`, deferred until normal mode) showing the failed version/source and the GitHub candidate from `update-kotlin-lsp.sh --preview`, offering to run `:KotlinLspUpdate`. Regression checks: `scripts/tests/kotlin_lsp_popup.lua`. It self-heals to ✓/⟳ once a live build attaches.

**Plugin organization by file:**
- `lsp.lua` — nvim-lspconfig + Mason (auto-installs LSP servers) + nvim-cmp (completion). nvim-lspconfig is `lazy = false` on purpose — see the note in the file; lazy-loading it on `BufReadPre` skipped brand-new files, and adding `BufNewFile` to *lspconfig* breaks filetype detection. `automatic_enable` is an **allow-list** equal to the `servers` list (`ensure_installed`), minus `rust_analyzer` when no Rust toolchain exists — so leftover Mason packages (emmet_ls, gradle_ls, sqlls, the stylua formatter's `lsp/` wrapper) never attach. `kotlin_lsp` is deliberately NOT listed (self-managed; kotlin.nvim enables it). `ensure_installed` additionally skips any not-yet-installed server whose Mason package must be built with a toolchain the machine lacks (npm, go, python3, cargo — read from the package's Mason source id), so a missing toolchain is not retried every start. tailwindcss starts only in Tailwind projects (`tajbanana/tailwind_root.lua`: upstream's root markers minus its bare `.git` fallback, which spawned it in every repo — a `tailwind.config.*` (also Django's `theme/static_src/`), a `package.json`/`deno.json` mentioning `tailwindcss`, or a postcss config / `mix.lock` / `Gemfile.lock` mentioning tailwind; one upward walk bounded by the repo root, nearest directory wins). gopls is dropped from both lists without `go` (Mason builds it with `go install`; an already-installed gopls stays installed but is not enabled). ts_ls's `root_dir` vetoes `@flow`-pragma JS/JSX (`tajbanana/flow_pragma.lua`: `@flow` as a word in a comment, not an `@flowio/…` import; regression checks `scripts/tests/flow_pragma.lua`; Flow sources drew thousands of bogus TS diagnostics) and otherwise delegates to upstream's `root_dir` (Deno veto, lock-file rooting, cwd fallback). On `LspAttach`, kotlin_lsp gets an `@` completion trigger and a rename handler that replaces its stale document versions. `<leader>gi` / `<leader>vws` open Telescope (`lsp_implementations`, `lsp_dynamic_workspace_symbols`).
- `colorscheme.lua` — onedark.nvim with a custom Material Darker-inspired palette and extensive treesitter/LSP highlight overrides
- `telescope.lua` — Fuzzy finder (file search, grep, keymap search, open-buffer picker with dd-to-close, diagnostics `<leader>xx`/`xb`, undo history, and the keys for `<leader>xr` and the `<leader>gc`/`gh` git pickers). `<C-p>` falls back to `find_files` outside a git repo; `<leader>ff` includes gitignored files when nvim-tree is showing them.
- `treesitter.lua` — Syntax highlighting with auto-install for parsers
- `formatting.lua` — conform.nvim (format-on-demand via `<leader>gf`, not auto-format; LSP fallback) and **mason-tool-installer**, which ensures the formatters (prettier, stylua, ktlint, ruff, goimports, gofumpt, shfmt) and the `<leader>xr` linters (golangci-lint, hadolint, yamllint) on every machine that can install them — toolchain-built ones are skipped where the toolchain is missing (`condition`s: goimports/gofumpt need `go`, prettier `npm`, yamllint a python3 that can create venvs), so a machine without them is not retried every start. `:MasonToolsClean` is replaced by a refusal (it would uninstall every LSP server). It loads at `VeryLazy` and calls `run_on_start()` itself, because the plugin's own trigger is a `VimEnter` autocmd that has already fired by then.
- `editor.lua` — Editing utilities (surround, autoclose, trouble, vim-test). Commenting is Neovim's built-in `gc`/`gcc` (Comment.nvim was dropped).
- `git.lua` — gitsigns (hunk nav `<leader>oo`/`pp` open a diff preview; `<leader>td` inline hunk preview; `<leader>dv` is `diffthis` against the buffer's *current* base — the fork point in the default view, the index in the working-tree view, as its description now says; gutter defaults to an IntelliJ-style whole-branch base = merge-base with the first of `main`, `master`, `origin/main`, `origin/master` that exists, cached per repo, HEAD *and* main/master ref SHAs, **re-applied to open buffers when HEAD moves** — each repo's git dir and `logs/` are watched with `vim.uv` fs_event (gitsigns' own events miss rebases and commits that keep the branch name), plus the data-less `GitSignsUpdate` and `FocusGained`; every git call is async (a pass never blocks the editor), the repo is the one gitsigns diffs against (`b:gitsigns_status_dict.root`), and `change_base` runs only when the fork point changed; a `<leader>gB` opt-out survives `:edit`; regression checks `scripts/tests/whole_branch.lua`, toggled per-buffer with `<leader>gB`), git-blame (inline), blame.nvim (per-line annotate pane on `<leader>gb`), lazygit (`<leader>lg`, always run with this repo's `lazygit/config.yml` via lazygit.nvim's custom-config option; fugitive removed: lazygit + gitsigns.diffthis cover it). surround, gitsigns, git-blame and indent-blankline load on `{ "BufReadPre", "BufNewFile" }` so brand-new files get them too.
- `ui.lua` — lualine (statusline; its `lualine_x` section includes the `tajbanana.lsp_status` LSP-load indicator), indent-blankline, nvim-tree (file explorer; `E` toggles scoped expand), which-key, fidget (LSP progress **and** `vim.notify`, via `override_vim_notify`; loads at `VeryLazy`)
- `kotlin.lua` — kotlin.nvim managing JetBrains kotlin-lsp (excluded from mason-lspconfig auto-enable). **Self-managed, not Mason-installed** (but kotlin.nvim prefers a Mason `kotlin-lsp` package over `KOTLIN_LSP_DIR` if one is present — uninstall it through `:Mason` to go back to the self-managed build): the `intellij-server` is a time-bombed EAP build that expires ~monthly and Mason's registry trails JetBrains by weeks (often only able to reinstall an already-expired build), so `kotlin.lua` points kotlin.nvim's `KOTLIN_LSP_DIR` fallback at the `~/.local/share/kotlin-lsp/current` **symlink path** (`KOTLIN_LSP_HOME` overrides the root) — every spawn, in every Neovim, follows the link. Do NOT hand it the resolved build path: Neovim's own FileType handler restarts from the previous launch's command, so updates then relaunch the old build (tried and reverted 2026-09-29; `scripts/tests/kotlin_launch.lua` guards it). Refresh flow on expiry is one command — **`:KotlinLspUpdate`** (runs `scripts/update-kotlin-lsp.sh`): it prefers the **latest GitHub release**, validates the build actually starts in an isolated probe, and only when that probe reports an explicit expiry does it offer the Open VSX `kotlin-server` build (from its `server-bundle.json`) behind a second confirmation. Downloads are sha256-verified, activation is an atomic `current` symlink swap, and the server reattaches in place with progress (phase + curl's byte %) in a fidget bar. The build that was current before is kept as a `previous` symlink (every other build is pruned — but nothing while any `…/current/bin/intellij-server` runs, without a process list, or when `current` did not point at a working build before the update; a server started from a versioned directory keeps its build, matched by the directory's name so a symlinked path counts; `current`/`previous` are used where they point, even outside the install dir; builds that probed as expired are listed in `.expired-builds` and never downloaded again, and a fallback build that is already current is reported UP-TO-DATE without a prompt), and **`:KotlinLspRollback`** swaps back after probing that it still starts (it refuses if the previous build has expired, is already current, or is gone; a failed swap is undone). Both commands exist before any `.kt` file is opened (lazy `cmd` trigger) and share a cross-process lock. `lsp_status.lua` surfaces the expiry as ⏱ and pops a small floating prompt that runs the update.
- `snacks.lua` — snacks.nvim image module: inline raster viewing (svg opens as XML; the markdown document-image preview is disabled); and its `input` module, which makes `vim.ui.input` a floating box at the cursor (so `<leader>rf` rename prompts in a popup pre-filled with the current name, not on the command line). snacks installs it on `UIEnter`, so headless runs keep the stock `vim.ui.input`.
- `markdown.lua` — render-markdown.nvim: in-buffer markdown rendering (headings, lists, tables, code) on the markdown filetype; `<leader>md` toggles it
- `lazy.lua` — lazy.nvim itself as a spec with `pin = true`, so `:Lazy update`/`sync` never bumps it and drifts `lazy-lock.json`; to upgrade, drop the pin, `:Lazy update`, re-pin, commit the lockfile

## Key Conventions

- **Plugin specs** follow lazy.nvim format: each `lua/plugins/*.lua` file returns a table with plugin name, dependencies, config/opts, and lazy-loading triggers (keys, event, cmd).
- **Keymaps** are defined in two places: global keymaps in `lua/tajbanana/set.lua`, plugin-specific keymaps in the plugin spec's `keys` field or `config` function.
- **LSP servers** are managed via Mason: add new servers to the `servers` list in `lsp.lua` (it is both `ensure_installed` and the `automatic_enable` allow-list), and add the filetype's primary server to `lsp_status.lua`'s `PRIMARY` table. LSP keymaps are set via `LspAttach` autocmd.
- **Formatters** are configured per-filetype in `formatting.lua` via conform.nvim's `formatters_by_ft`; add the tool to mason-tool-installer's `ensure_installed` in the same file so it installs everywhere.
- **Filetypes**: custom detection lives in `set.lua`'s `vim.filetype.add` (Helm templates and values, compose, GitLab CI, gotmpl, .iml). Compound YAML filetypes resolve back to `yaml` for treesitter and conform; code that checks `filetype == "yaml"` must also accept `yaml.*`.
- **Color customization** uses treesitter highlight groups and LSP semantic tokens in `colorscheme.lua`. Use `:Inspect` to find the highlight group under the cursor.
- **Lua in this repo is hand-formatted; stylua is NOT enforced repo-wide.** 28 of 32 `.lua` files (`init.lua` + `lua/**`) currently differ from `stylua.toml` (measured 2026-09-30 with stylua 2.5.2) — partly `collapse_simple_statement = "Always"`, which the hand-written code ignores in favour of expanded guards (it accounts for 10 of the 28; with it off, 18 still differ, from manual alignment and wrapping). Consequence: running `<leader>gf` on a Lua file reformats guards you did not touch, producing unrelated diff noise. Match the surrounding file's style when editing rather than the config, or reformat the whole repo deliberately in its own commit — but do not do it incidentally.

## Symlinks

The `.ideavimrc` should be symlinked to `~/.ideavimrc`, and `starship.toml` (the
shell prompt, not Neovim) to `~/.config/starship.toml`:
```
ln -s ~/.config/nvim/.ideavimrc ~/.ideavimrc
ln -s ~/.config/nvim/starship.toml ~/.config/starship.toml
```

`lazygit/config.yml` needs no link for `<leader>lg` — lazygit.nvim passes it
explicitly. For *terminal* `lazygit`, link it into lazygit's per-OS config dir
(`lazygit -cd` prints it): `~/Library/Application Support/lazygit` on macOS,
`~/.config/lazygit` on Linux/WSL:
```
ln -sfn ~/.config/nvim/lazygit/config.yml "$(lazygit -cd)/config.yml"
```

`git/delta.gitconfig` is *included* rather than symlinked, so `git config
--global` edits and this repo never overwrite each other:
```
git config --global --add include.path ~/.config/nvim/git/delta.gitconfig
```

## Validating Changes

There is no build step. Regression checks live in `scripts/tests/` (headless Lua plus one offline Python suite); run them all with:
```
bash scripts/tests/run_all.sh
```
It executes the line-1 `Run:` header of each `*.lua` / `*.py` file there, so a new test in either language only needs that header to be included. The indent-scope and incremental-selection tests need the treesitter parsers installed (see [readme.md](readme.md#validating-changes)); `indent_scope.lua` and `whole_branch.lua` also load indent-blankline / gitsigns from lazy's install dir. Also verify interactively:
1. Open Neovim and check for errors: `:messages`
2. Run `:checkhealth` to verify plugin health
3. Run `:Lazy` to check plugin status and sync if needed
4. For LSP changes: `:LspInfo` to verify server attachment
5. For treesitter changes: `:lua =require("nvim-treesitter").get_installed()` to list installed parsers
